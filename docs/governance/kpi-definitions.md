# RWC 阶段四（4-8）KPI 定义

> 说明：以下 KPI 统一按「名称 | 当前值 | 目标值 | 度量方式 | 责任人」定义，按周/月在治理例会上复盘。

## 1) 工程质量 KPI

| 名称 | 当前值 | 目标值 | 度量方式 | 责任人 |
|---|---:|---:|---|---|
| CI 通过率 | 100% | 保持 100% | 统计默认分支近 30 天 CI run 成功数 / 总 run 数 | 后端负责人 |
| 测试覆盖强度（后端测试数量） | 101+ 测试 | 保持 101+ 且随功能增长 | `pytest --collect-only` 统计测试用例数量，按迭代对比 | 后端负责人 |
| npm audit 高危漏洞数（high） | 6 | ≤ 3 | 每周执行 `npm audit --audit-level=high`，记录 high 数量 | 前端负责人 |
| 安全漏洞响应时效（SLA） | 已建立分级 | P0 ≤ 4h；P1 ≤ 24h；P2 ≤ 1 周 | 从漏洞登记时间到修复合并时间，按等级统计达标率 | 安全负责人 |

## 2) 开发效率 KPI

| 名称 | 当前值 | 目标值 | 度量方式 | 责任人 |
|---|---:|---:|---|---|
| 每周 Commit 数 | ~10 / 周（本周基线） | ≥ 10 / 周（稳定） | GitHub 默认分支 + 活跃开发分支每周 commit 总数 | Tech Lead |
| PR 合并时间 | 待建立基线 | < 24h（中位数） | PR 从创建到 merge 的中位耗时（排除草稿和阻塞项） | Tech Lead |
| Issue 关闭率 | 待建立基线 | ≥ 80% / 月 | 月度关闭 issue 数 / 当月新增 issue 数 | 项目经理 |

## 3) 社区 KPI

| 名称 | 当前值 | 目标值 | 度量方式 | 责任人 |
|---|---:|---:|---|---|
| GitHub Stars 增长 | 待建立基线 | 净增长 ≥ 5 / 月 | 月初与月末 star 数差值 | 社区运营 |
| 外部 PR 数量 | 待建立基线 | ≥ 3 / 月 | 统计作者非核心团队成员的已创建 PR 数量 | 开源负责人 |
| 社区帖子互动率 | 待建立基线 | ≥ 15% | （评论 + 点赞 + 收藏）/ 帖子曝光量（或浏览量） | 社区运营 |

## 4) 产品 KPI

| 名称 | 当前值 | 目标值 | 度量方式 | 责任人 |
|---|---:|---:|---|---|
| API 端点可用性（Uptime） | 待建立基线 | ≥ 99.9% / 月 | 基于健康检查与监控探针计算 API 月度可用性 | SRE / 后端 |
| MCP Server 集成数 | 待建立基线 | ≥ 10（阶段目标） | 统计已接入并通过验证的 MCP Server 数量 | 产品负责人 |
| 模块 Registry 收录数 | 待建立基线 | ≥ 30（阶段目标） | 统计 Registry 中可用模块条目数量（去重） | 平台负责人 |

---

## 复盘节奏与数据口径

- 复盘频率：每周快速检查 + 每月正式复盘。
- 数据来源：GitHub（PR/Issue/Commit/Stars）、CI 平台、安全扫描报告、运行监控系统、Registry 台账。
- 口径原则：所有 KPI 采用可追溯原始数据，禁止人工估算替代系统统计。
